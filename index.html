巨天工作室 Jutian Studio — Independent, Small, Sharp

一间独立运作的小型技术工作室。我们不做平台，也不追风口，只做一件事： 把原本需要折腾半小时的麻烦事，压成一次双击、一条命令、一个链接。

目前三条产品线并行——macOS 原生桌面工具、基于浏览器的 3D 与编辑器增强、 以及跑在本地的智能体。所有代码公开在 GitHub，许可宽松，欢迎翻、欢迎改、欢迎提意见。

简单说

巨天工作室成立于 2026 年 8 月，由一名中学生独立运营。没有融资，没有团队， 也没有路线图 PPT。判断一个想法值不值得做，只用一条标准：做完之后， 会不会有人真的每天用它。

如果你只是路过，直接从上面的目录跳到你感兴趣的那节就行，不用从头读。

关于工作室

我们是谁、为什么存在、以及不做什么。

我们是谁

没有流程，也不打算有

巨天工作室成立于 2026 年 8 月。它最初只是 GitHub 上的一个账号， 用来放一些"自己要用、但世上没有"的小工具；后来东西越堆越多， 就干脆给它起了个名字。

工作室目前只有一个人。这不是谦虚，是事实。这意味着迭代很快、沟通链路极短， 也同样意味着有些事情做不完、有些 Bug 修得慢。我们选择把这一点写在官网上， 而不是包装成某种"精英小团队"的说法。

产出大致分三类：把命令行的繁琐流程包装成图形界面的桌面工具； 用浏览器自动化去增强已有的在线编辑器；以及在网页里重建 3D 世界。 这三类看似散，动机其实一样——降低使用门槛，让技术不再只属于会敲命令的人。

不做的事

我们不做的几件事

  • 01不做账号体系。能用本地文件解决的，绝不要求注册登录。
  • 02不做数据收集。所有作品都不含埋点、不含统计脚本、不含遥测。
  • 03不做付费墙。已发布的项目全部免费开源，没有"专业版"。
  • 04不做半成品宣传。东西没跑通之前不发预告，跑通了才写文档。
  • 05不做长期维护承诺。项目随缘维护，但代码开源，任何人可以接手。

2026-08-28

把编程猫 KittenN 积木编辑器，整套换成深色玻璃质感。

KittenN 是使用量很大的积木编程编辑器，但它默认只有浅色界面， 长时间盯着看眼睛很累，夜间尤甚。这个项目的做法很直接：不是写油猴脚本 去打补丁，而是用 Playwright 驱动本机已有的 Chrome 打开编辑器， 再注入一套完整的深色主题样式。

选择 Playwright 而不是浏览器插件，是为了绕开登录态问题—— 脚本直接使用你本机浏览器的真实配置，登录一次后会话保存在本地目录， 之后每次启动都不需要重新登录。同时因为走的是标准浏览器， macOS、Linux、Windows 三端行为一致。

  • 01界面外壳、积木工具箱、代码工作区、控制台、变量与列表面板统一深色
  • 02按钮改为半透明毛玻璃：细描边加内高光，悬停上浮、按下收缩
  • 03顶栏保存 / 发布 / 撤销重做 / 缩放等按钮全部重做样式
  • 04右键菜单、添加角色、变量编辑器等原生弹窗保持原样，不破坏交互
  • 05作品封面图与积木贴图正常显示，不会被滤镜反色
  • 06首次运行自动检测 Node 版本、依赖、浏览器路径与网络连通性

Box3Blocks 方块表
更新
2026-08-29

不用装客户端，在浏览器里打开地图，直接走进去。

Dao3 / Box3 是一个方块创造类平台，玩家在里面搭出各种地图。 但想看别人做好的地图，通常只能看截图或视频——除非下载专门的客户端。 Arcadia Base 想解决的就是这件事：把运行器搬到网页里，输入地图 ID 或把导出的压缩包拖进页面，就能在浏览器里以 3D 方式自由漫游。

技术上最麻烦的是方块贴图。项目在构建阶段把 Box3Blocks 的方块 ID 主表、 渲染规则与 16×16 贴图合成一张图集，运行时完全离线， 不依赖任何外部图床。流体部分做了同材质内部面剔除， 否则一整片水的内部面会白白消耗大量填充率。

  • 01384 种方块，使用真实贴图，构建期合成图集
  • 0213 种流体：水、岩浆（自发光）、果汁等，同流体内部面自动剔除
  • 03模型实体按位置、旋转、缩放还原，侧边栏可查看解析状态
  • 04三套相机：预览环绕、第一人称、第三人称（含胶囊碰撞与跳跃）
  • 05支持自建部署：Docker 镜像或本地 npm start 均可

2026-08-28

在 Mac 上跑 Windows 程序，不装虚拟机，不敲命令。

macOS 用户偶尔会碰到一个 .exe：学校的教学软件、某个只有 Windows 版的小工具、 同事发来的安装包。为了一个几十兆的程序去装虚拟机或双系统，成本显然太高。 Wine 是现成的兼容层，但它本身是命令行的，还得处理 X11 显示、前缀配置、 环境变量这些细枝末节。

WineAppRunner 就是把这些细节收进一个图形窗口：选文件、点运行、 下方实时滚动日志。首次启动会检查 Wine 与 XQuartz 是否存在， 缺失时给出可直接执行的安装命令，而不是丢一句"请先安装依赖"就完事。

  • 01图形界面选择 exe，运行日志实时输出，便于排查失败原因
  • 02内置依赖检测与安装引导，含 Homebrew 命令一键复制
  • 03打包为独立 .app，双击即用，不占用终端
  • 04常见问题写进 README：XQuartz 缺失、PATH 找不到 wine 等

一个长在你电脑里的智能体，而不是又一个聊天框。

巨天 Agent 是工作室目前投入最多的项目。它不是一个网页对话框， 而是一个跑在本地的桌面应用：能开终端执行命令、能读写磁盘上的文件、 能打开内置编辑器改代码、能把一句话大纲变成整套 PPT， 也能听你说话、开口回答。

和常见 AI 助手最大的区别是"手"——它有真实的操作能力，而不只是生成文字。 相应地，控制权也交还给用户：思考分五档，从秒回到深度推理， 由你决定这次要不要多花点时间。

原则

选型的三条硬规矩

  • 01能用一个脚本解决的，不引入框架。依赖越少，半年后越可能还跑得起来。
  • 02能跑在本地的，不强迫上云。用户的数据默认留在用户的硬盘上。
  • 03能不改用户习惯的，就不改。工具应该适配人，而不是反过来。

工作方式

从想法到发布，中间到底发生什么。

  1. 01

    先自己用一周

    任何工具的立项前提是自己真的会用到。写完之后先自用一周，如果一周后自己都懒得打开，这个项目就停掉，不对外发布。

  2. 02

    安装路径必须最短

    我们把"从下载到跑起来"当作硬指标。能双击就双击，能一条命令就一条命令。需要改配置文件才能启动的设计，一律重做。

  3. 03

    错误信息写给人看

    报错不要只抛异常堆栈。检测不到依赖就给出安装命令，网络不通就说清是哪一步不通。能自动修的自动修，不能自动修的说清楚怎么手动修。

  4. 04

    文档与代码同步写

    README 不是发布前的补作业，而是开发过程中的副产品。每个功能的说明在功能完成当天写完，包括它做不到什么。

  5. 05

    公开发布即开源

    所有作品发布时同步公开源码，许可尽量选宽松的。我们不做"社区版 / 专业版"，也不把核心功能藏起来。

常见问题

被问过、或者迟早会被问到的问题。

工作室是公司在运营吗？

不是。目前没有任何公司实体，也没有团队成员，全部工作由一个人完成。就是字面意义上的一个人，没有别的说法。

为什么所有项目都开源？

两个原因。一是这些工具本来就是为"自己要用"而写的，开源不会损失什么；二是开源之后别人可以直接接手，项目不至于因为某天没人维护就彻底消失。

项目会长期维护吗？

不做承诺。活跃的、自己每天都在用的项目会持续更新；用不上的会进入低频维护状态。所有代码开源，任何人都可以 fork 出去继续做。

如果你希望接手某个项目的维护，直接开 Issue 说就行，我们很乐意把维护权交出去。

可以商用吗？

看具体项目的许可证。KittenN Cyberpunk Editor 是 MIT，可以商用；Arcadia Base 沿用上游 box3lab/Arcadia-base 的许可条款，商用前请先确认上游要求。涉及方块贴图与地图数据的部分请自行确认授权。

巨天 Agent 什么时候能下载？

目前是预览版，尚未开放下载，也没有确定的发布日期。可以确定的是两个平台都会做：macOS（Apple Silicon）与 Windows（x64）。发布消息会在 GitHub 与巨天 Agent 官网同步。

网站有没有统计脚本或 Cookie？

没有。这三个站点都是纯静态页面，不含统计、不含广告、不含 Cookie，也不加载任何第三方资源。深浅主题偏好存在浏览器 localStorage 里，只在本机生效。

发现了 Bug 怎么反馈？

在对应仓库开 Issue 是最快的方式。请附上系统版本、项目版本、复现步骤和完整报错信息——尤其是终端里的原始输出，比截图有用得多。

可以找工作室做定制开发吗？

目前不接商业项目。如果你有一个具体的、开源的小工具想法，可以开 Issue 聊，觉得有意思的话我们有可能会做。
